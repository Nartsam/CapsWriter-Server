# 热词跨设备同步

客户端仅连接当前识别服务端。服务端管理 `hot.txt`、`hot-rule.txt`、`hot-server.txt`，在启动和正常退出时与独立 Git 仓库同步；服务端之间不用互相访问或同时在线。客户端保存后的修改经独立 WebSocket 连接立即传给当前服务端，并通知它的其他在线客户端。

## 配置

`config_server.py` 的 `HotwordSync.repository` 默认是 `Vartsam/CapsWriterConfig`，可填写 `owner/repo`、HTTPS Git URL 或 SSH Git URL。各服务端填同一个仓库。空字符串关闭远端 Git 同步，客户端与服务端之间仍会同步。

服务端机器需要安装 Git，并使**运行服务端的用户**具有该仓库读写权限。默认使用 Git 已有的凭证管理器或 SSH 身份，不弹登录窗口；桌面用户登录状态不会自动传给另一台 Linux 机器或服务账户。

可选：在服务端 `assert/config_repo_token.txt` 写入一行 GitHub PAT。此文件已经被 Git 排除；目录和文件都可以不存在，需要使用密钥时再创建。不要把密钥写进配置文件或仓库地址。程序只在 Git 子进程环境中使用密钥；文件不存在、内容无效或认证失败时回退已有 Git 登录。远端不可访问、Git 未安装或无写权限时记录警告，继续识别和本地同步，待下次启动或退出重试。

客户端不用配置 Git、仓库地址或密钥。只有它已经选中的识别服务端会接收热词同步连接，路径为 `/hotword-sync`，与音频共用监听端口。

## 文件与生效时间

| 位置 | 内容 |
|---|---|
| 客户端根目录 `hot.txt`、`hot-rule.txt` | 用户编辑的正式词库，不再由客户端程序仓库跟踪 |
| 服务端根目录 `hot-server.txt` | 识别概率热词，不再由服务端程序仓库跟踪；保存后下次识别生效 |
| 两端 `logs/hotword_sync/` | 必要同步基线、未完成应用的状态和客户端冲突文件 |
| 服务端 `logs/hotword_sync/git/` | 独立配置仓库的 Git 对象与三个热词文件；不要在这里手工编辑 |

程序缺失正式文件时会创建并同步。第一次同步合并双方已有内容；以后以共同基线判断新增、修改和删除。基线按曾连接的服务端保存，不累积全文操作历史。不要把 `logs/hotword_sync/` 当普通日志清空；丢失基线后会重新按首次同步合并。

客户端的保存、创建及编辑器替换文件事件按文件防抖约 0.4 秒处理，不定时轮询内容。断网期间继续使用本机文件，重连后补传。服务端远端同步仅在启动/正常退出执行：一直在线的两台服务端不会定时从 Git 拉取，关闭终端或强杀未完成的远端上传在下次启动重试。客户端正常退出最多短暂等待本轮同步，强制结束时本地修改仍可在下次连接补传。

升级其他已有安装前，先把原来的三个热词文件备份到对应 `logs/hotword_sync/` 下，再更新代码并恢复正式文件，避免 Git 的取消跟踪删除尚未同步的个人内容。本机此次取消跟踪保留了原文件。

## 合并与冲突

- 相同目标的别名合并：`Claude | 克劳德` 与 `Claude | 克劳得` 变为 `Claude | 克劳德 | 克劳得`。共同基线里已存在、后来被删除的别名不会无条件补回。
- 相同内容去重，保留注释、空行和既有排版，规则不排序；未变化的行保持原写法。
- 服务端概率热词自动合并。单方修改加分正常传播；双方同时改成不同加分时取较低值。不写加分按当前默认值比较。删除与另一侧修改并发时保留修改的一侧。
- 客户端同一正则模式的不同替换式、删除与修改冲突，需要处理冲突稿；互不影响的修改先自动合并。规则顺序的重叠变更可能需要整文件确认。

发生冲突时，受影响客户端收到 8 秒后消失的 Toast，并在 `logs/hotword_sync/` 生成 `hot.conflict.txt` 或 `hot-rule.conflict.txt`。正式词库仍可使用，该文件的同步暂停。按文件顶部说明编辑，删除全部冲突标记后保存。保存/替换事件触发格式检查，服务端确认持久保存并成功更新本机正式文件后，冲突稿永久删除；生成的说明块不进入词库，用户注释保留。

Git 拉取产生的规则冲突也由客户端处理。远端上传会等这些冲突处理完成，本机识别不受影响。配置仓库每次只提交有变化的热词；并发推送被拒绝时重新获取并合并，不强制推送。

## 开发验证

`python tools/test_hotword_sync.py` 用标准库验证合并、持久化及本地 Git 仓库中的双服务端同步，不访问私人远端。客户端同名测试还覆盖冲突处理和文件事件，并已登记到 `tools/run_tests.py`。`core/hotword_sync.py` 在两个程序仓库必须保持逐字相同，兼容 Python 3.8。

`tools/test_hotword_transport.py` 是可选的跨端源码联测，用真实 WebSocket 和 watchdog 验证保存/替换事件、广播、冲突解决与 A→B→A 切换。只有显式传入 `--client-root <可读取的客户端源码根目录>` 才加载对端源码；未提供时明确跳过，不搜索其他目录。客户端仅在另一台机器上时，本端仍可独立运行 `test_hotword_sync.py`，实际跨机联调通过客户端配置的服务端网络地址完成。

联测的临时状态留在本仓库 `logs/` 并自动清理；需要测试环境已有 watchdog 和 websockets，Windows Python 3.13 也可读取服务端随附的 websockets，不启动识别模型。
