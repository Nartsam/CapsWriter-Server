# 角色请求整段识别

客户端先用流式结果判断是否命中角色，再要求服务端从完整原始录音重新执行普通识别。角色选择、图片、连续对话和 LLM 请求由客户端管理。

## 协议约定

字段、默认值和序列化定义见两端共用的 [`core/protocol.py`](../core/protocol.py)。两端同步更新，线上结果显式携带阶段与识别模式。

只有 `source=mic, streaming=True, revisable=True` 进入可重识别流程。普通麦克风、纯流式听写和文件转录不保存完整录音副本。录音各包的 `source`、`streaming`、`revisable` 必须一致；上下文、语言、分段参数和录音开始时间沿用首包快照。

音频、结束包和 `RecognitionControlMessage` 使用同一 WebSocket 的有序发送通道，控制消息携带原录音 task_id：

| action | 行为 |
|---|---|
| `request_full` | 停止预览，音频收齐后普通重识别；已收齐则立即开始 |
| `commit_stream` | 释放原始音频副本，采用流式结果；尾段已完成则立即发终局 |
| `cancel` | 取消未终结任务，释放缓存，发送 cancelled 终局 |

同一决定重复到达保持幂等；冲突决定记日志并沿用首次决定；cancel 可以覆盖未终结决定，终局之后不再重开。控制仅操作当前连接的任务。录音中取消时客户端先发送音频结束包，再发 cancel；未发送音频的短按取消无需控制请求。

## 结果与时序

`AudioMessage.is_final` 只表示音频输入结束。识别结果的阶段含义：

- `partial`：`is_final=False`。stream 的 delta 可供普通听写增量输出；full 的 delta 为空，只报告进度。
- `decision`：仅用于未决预览，`is_final=False, recognition_mode=stream, status=ok`。text 是完整候选，delta 是尚未输出的尾段。客户端此时只作决定，不上屏、不归档、不消费图片或任务快照。
- `final`：`is_final=True`，每个任务最多一次。commit_stream 后沿用 candidate 的尾段 delta；客户端只在 final 时消费它。full 的 text 是从零开始普通识别的全文，delta 为空。
- `error`、`cancelled` 只用于 final，text、delta、tokens 等文本结果为空；普通识别失败不回退到流式候选。

音频结束前已 commit_stream：最后直接回 stream final；已 request_full：收齐后启动 full。未决：回 decision，继续保留音频直到决定或断线，没有短时限。客户端进入等待 full 后忽略在途的旧 stream 帧；服务端接受 full 后不再发布新的 stream 帧。

time_start 保持原录音时间。duration 按实际音频长度计算，预览和重识别、重叠窗口均不累加；full 的 time_submit 是普通重识别阶段开始提交的时间。客户端提醒基准仍为 `time_start + duration`。

## 实现与资源

[`connection/recognition.py`](../core/server/connection/recognition.py) 按连接管理独立录音，原始 PCM 从首包存入 `logs/role_full_asr/` 下的 `TemporaryFile`，包含已切走的句子和 silent 音频。每个 full 任务只投递一片，结果返回后再读取下一片；最后一片读完、取消、错误、断线或服务退出时关闭缓存。

full 使用新 worker session，共用普通切片与拼接流程，不继承预览文字或 prefix_text。缓冲与 session 以 `(socket_id, task_id, recognition_mode)` 隔离；丢弃指令与音频共用输入队列，正在推理的旧片段自然完成，主进程过滤其迟到结果。最新会话优先、同阶段 FIFO 的调度保持不变。

接收决定和结果发送共用连接锁，主进程在 await 前认领唯一终局。已终结任务保留 ID，直到连接关闭，以拦住迟到音频和控制。

普通识别仍受模型现有 chunk_size 限制。full 切片超限时明确返回 error，避免适配器静默截断；解码重试后仍熔断也返回 error。音频总时长没有新增限制，长录音按现有 seg_duration / seg_overlap 分段。

## 验证

离线测试运行真实接收、流水线与发布代码，使用假引擎；测试临时文件自动清理：

```bash
python -B tools/test_recognition.py
```

Windows 启动一个独立测试实例 `start_server.exe --port 6100`（Linux 为 `./start_server.sh --port 6100`），先运行原 smoke_test.py 的普通、`--source file`、`--seg-duration 6 --seg-overlap 2`、`--streaming` 四项，再运行：

```bash
python -B tools/smoke_test_revisable.py --port 6100 --action request_full --when early
python -B tools/smoke_test_revisable.py --port 6100 --action request_full --when decision --seg-duration 6 --seg-overlap 2
python -B tools/smoke_test_revisable.py --port 6100 --action commit_stream --when early
python -B tools/smoke_test_revisable.py --port 6100 --action commit_stream --when decision
python -B tools/smoke_test_revisable.py --port 6100 --action cancel --when early
python -B tools/smoke_test_revisable.py --port 6100 --action cancel --when decision
```

探针检查阶段、时序、delta 消费、重复控制和唯一终局。流式任务检查 delta 拼接等于 text；full 排除旧预览。模型有采样随机性，输入字节和分段一致性由离线测试验证。
